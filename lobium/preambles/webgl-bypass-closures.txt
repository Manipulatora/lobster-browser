Lobium - two paths where the persona's WebGL description was silently not applied.

Both were found by auditing the readback and enumeration entry points against the CALL SEQUENCES a
detector actually uses, rather than the ones a normal renderer uses. They are one patch because they
are one defect class: a legal but unusual call that routes around a hook which looked complete.

1. readPixels with a non-default pack alignment
   ------------------------------------------------------------------------------------------------
   The farble gate required the DEFAULT pixel-store state, so gl.pixelStorei(PACK_ROW_LENGTH, width)
   switched it off - and setting PACK_ROW_LENGTH to exactly the row width is a BYTE-FOR-BYTE NO-OP.
   Two reads, one line apart, returned farbled pixels and then the true GPU pixels. That is worse
   than not farbling at all: it hands over the real fingerprint AND proves something is rewriting it.
   The gate now keys on the effective geometry (skip_pixels, skip_rows and an effective row length at
   least the read width) so a no-op setting stays on the farbled path.

   The same change also covers reads from a user framebuffer, which were skipped entirely. A page can
   render to its own FBO and read from that, so leaving it uncovered left the whole surface
   reachable. Opaque framebuffers stay excluded, because their contents are not the drawing buffer.

2. getSupportedExtensions on a WebGL2 context
   ------------------------------------------------------------------------------------------------
   The function is shared by WebGL1 and WebGL2, and matches configured names against `extensions_`,
   the registrations for THIS context. WebGL2 folds several WebGL1 extensions into core - instanced
   arrays, vertex array objects, depth texture, draw buffers, the float texture family - so a
   WebGL1-shaped list handed to a WebGL2 context matched only the handful of names common to both.
   The result was a WebGL2 context advertising a fraction of the extensions any real browser reports,
   which is a tell in its own right. The list is now chosen per context type from the config's
   separate WebGL1 and WebGL2 lists.

Cut against fingerprint/webgl-surfaces.patch, fingerprint/host-gpu-profile.patch and
fingerprint/webgl-runtime-safety.patch, and mechanically verified to reproduce the checkout when
applied after them. It cannot be applied to a pristine tree; never validate it in isolation.

Hook point: third_party/blink/renderer/modules/webgl/webgl_rendering_context_base.cc
